# BBS 文章與精華區備份研究及實作規劃

研究日期：2026-11-09（Asia/Taipei）

## 結論

第一個目標為 PTT2 的 使用者個板（板名待使用者於工具輸入） 個人板，使用者已確認具有板主權限，並於 2026-11-09 回報：小寫 u 備份功能失效，現行看板 h 說明也沒有備份指令。因此撤回官方整包備份優先的建議，改以「登入式終端機下載器＋本機離線閱讀器」為主要方案。先驗證現行登入、文章讀取及精華區走訪，再擴大下載；後續擴充 PTT 班板與夢之大地班板。

已讀取先前對話「26'0116 BBS爬蟲備份瀏覽器開發」：既有偏好是 Windows、本機程式搭配瀏覽器介面、可離線閱讀。當時僅有規劃，不能視為已有可用程式。此次專案目錄檢查未發現現有實作；本機 Python 實際回報 3.12.6。

這次完成公開資料研究與未登入的連線探測，尚未登入 使用者個板（板名待使用者於工具輸入）、申請備份或取得任何文章。不能把連線端點可用解讀為完整備份已驗證。

## 1. 已排除為主要方案：舊版 PTT2 官方整包備份

以下僅記錄歷史文件，不是目前可執行的操作指引。使用者已實際確認 u 失效且 h 說明沒有備份入口，不再要求重試舊指令。

舊版官方專案 Wiki 的操作方式：

1. 以板主帳號進入自己的個人板，在文章列表按小寫 `u`。
2. 確認看板名稱為 使用者個板（板名待使用者於工具輸入），確認備份。
3. 設定通知信箱；可使用站內通知。
4. 「備份看板內容」選 Y。
5. 「備份精華區內容」也選 Y；文件中的預設值是 N。
6. 等候排程與通知，依實際通知下載全部相關備份檔。

舊文件寫明下載期限為收到通知後 24 小時；FAQ 寫排程通常於當日或隔日凌晨 3 點左右處理。這些是文件描述，並非對目前站台服務時間的保證。歷史範例使用 HTTP 下載網址，不能因登入採用 WSS 就認定備份檔的下載也有 TLS；實作時須辨識通知中的實際 URL 與可用協定。

官方 FAQ 描述整包備份能保留文章列表、日期、作者、推文數、文章標記、置底與 ANSI 等資料，並包含較逐篇讀取更完整的看板資訊。回收桶、編輯紀錄是否實際包含，需檢查這次取得的檔案，不先承諾可復原所有歷史刪文。

此方法曾能一次保存數千至上萬篇以及精華目錄，但文件仍存在不代表現行站台仍提供服務。板主權限也不能解決已停用或不再提供的操作入口。

尚無可靠公告可確認其精確移除日期、是否只是部署設定改變、或是否存在新入口；不能宣稱已找到對應移除 commit。這些不確定性不阻擋下載器規劃。只有未來取得可驗證的新入口或既有備份檔，才重新評估整包匯入。

近期改版的獨立佐證：BePTT 於 2026-11-06 修正 PTT2 登入畫面改版相容性；2026-11-05 調整進入看板、讀取文章及連續指令速度。這支持近期介面確有變動，但不能證明備份功能在同一天移除。[BePTT 更新紀錄](https://beptt.tw/release/ios/)

來源：[官方備份步驟](https://github.com/ptt/pttbbs/wiki/ptt2backup)、[官方 FAQ](https://github.com/ptt/pttbbs/wiki/ptt2backupFAQ)、[官方匯入說明](https://github.com/ptt/pttbbs/wiki/ptt2backupExport)。前兩篇已透過 raw.githubusercontent.com 的 Wiki 原始 Markdown 成功讀取。

## 2. 安全連線現況與實測

BePTT 開發者於 2026-11-05 公告 PTT／PTT2 WSS 異常，建議暫時改用 SSH。這證明單一連線方式存在故障風險，但不能據此推定 11 月 9 日仍故障。

本機於 2026-11-09 21:48（台北時間）進行各端點一次探測，沒有輸入 BBS 帳號或密碼：

| 站台 | WSS 端點 | WSS 結果 | SSH 端點 | SSH 結果 |
|---|---|---|---|---|
| PTT2 | `wss://ws.ptt2.cc/bbs` | HTTP 101，驗證 Sec-WebSocket-Accept，收到 binary frame | `ptt2.cc:22` | 回覆 SSH-2.0-bbs-sshd |
| PTT | `wss://ws.ptt.cc/bbs` | HTTP 101，驗證 Sec-WebSocket-Accept，收到 binary frame | `ptt.cc:22` | 回覆 SSH-2.0-bbs-sshd |
| 夢之大地 | `wss://ws.ccns.cc/bbs` | HTTP 101，驗證 Sec-WebSocket-Accept，收到 binary frame | `ccns.cc:22222` | 回覆 SSH-2.0-bbs-sshd |

WSS 使用系統憑證驗證，沒有關閉 TLS 驗證。探測使用各站官方終端機網址作 Origin，不能據此斷言任意 file:// 或 localhost 網頁可直接連線。SSH 僅讀取服務 banner，未進行 SSH 認證、主機金鑰驗證或 BBS 登入。初始 WSS frame 未解析成登入畫面。

工程決策：WSS 可作第一個實作通道；另設 SSH transport，於中斷後退避重試並從任務紀錄恢復。不能將 PyPtt 的 Telnet 選項誤認為 SSH，也不以舊式明文 Telnet 作預設備援。

來源：[BePTT 2026-11-05 公告](https://beptt.tw/announce/ptt-wss-connection-issue-261105/)、[PTT 官方終端機程式](https://github.com/ptt/ptt-term)、[夢之大地伺服器專案](https://github.com/ccns/dreambbs)、[夢之大地終端機](https://github.com/ccns/PttChrome)。

## 4. 建議交付形式

先做本機 Python 核心＋瀏覽器介面；若需要免安裝 Python，再封裝 Windows exe。下載器與閱讀器共用資料格式，介面不綁死通訊協定。

預期使用流程：雙擊啟動 → 瀏覽器開啟本機頁面 → 使用者登入 PTT2 → 選擇 使用者個板（板名待使用者於工具輸入） 與備份範圍 → 小樣本驗證 → 建立全量任務 → 看進度與失敗清單 → 搜尋與閱讀。

離線閱讀分兩種：

- 本機應用程式：斷網仍可啟動與全文搜尋，資料由 SQLite 管理。
- 可攜靜態 HTML 匯出：雙擊 index.html 即可讀文章、目錄與搜尋索引；資源全部隨檔附帶，避免依賴 CDN 或 file:// 下的 fetch 限制。

第一版需提供現行終端機畫面與人工登入入口，包含必要的二階段驗證與登入提示。驗證完登入狀態後才啟動自動讀取；不假設 PyPtt 已完全相容 11 月的改版。即使未來將核心封裝 exe，也仍可保留瀏覽器操作方式，兩者並不衝突。

## 5. 實作階段與驗收

| 階段 | 工作 | 驗收與分支 |
|---|---|---|
| A：現行介面驗證 | WSS 連線、人工登入、進 使用者個板（板名待使用者於工具輸入），辨識列表、文章與精華畫面 | 取得可重播的去敏測試樣本；驗證中文、控制碼與目前可用閱讀按鍵 |
| B：少量下載 | 一般文 20 篇與一個多層精華子目錄，保存內容、來源與階層 | 長短文、推文、特殊字元及翻頁內容比對正確；部分下載不得記為成功 |
| C：穩定性與全量 | 200 篇試跑、限速、失敗清單、斷線續傳，通過後下載全板及精華；驗證 SSH 備援 | 中斷後可恢復，重跑不產生不必要重複，結尾重新掃描對帳；依實測估算時間 |
| D：離線閱讀器 | 文章列表、精華樹、作者／日期篩選、中文全文搜尋、TXT/JSON/HTML 匯出 | 斷網可開啟；至少抽查 30 篇，涵蓋長文、ANSI、推文、特殊字元及多層精華 |
| E：跨站擴充 | PTT 班板適配；夢之大地獨立畫面與目錄解析器 | 各站分別通過樣本、斷線續傳與離線比對，不能只換 hostname 宣稱支援 |

下載器需處理實際收到的位元組、終端機控制碼與畫面更新，另外產生 UTF-8 可搜尋文字。Big5／UAO、UTF-8 的選擇由來源驗證，不一律以錯誤替代字元覆蓋。終端機資料流包含翻頁與畫面重繪，不等同伺服器原始文章檔；可讀內容與可見 ANSI 外觀需分別驗證，不能承諾位元組相同的原始檔復原。若未來取得舊版 tgz，才另外實作 .DIR 二進位索引匯入。

一般文章與精華條目分開建模。相同文章可以出現在多個精華路徑；內容可共用，但目錄位置、排序與不同版本不得因去重而丟失。優先使用來源檔名、AID 或完整精華路徑識別來源，不只依會變動的畫面編號。

## 6. 逐篇下載的完整性設計

- 先建清單與任務狀態，再讀內容；保留成功、失敗、權限不足、來源已刪除、需重試等結果。
- 單一連線逐篇讀取，依伺服器回應自適應等待；不使用多帳號或大量平行連線。
- 偵測到站方冷卻、資源限制或驗證提示就暫停並顯示原因；SSH 只作連線相容性備援，不用來繞過帳號或頻率限制。
- 以終端機畫面狀態判斷是否可繼續操作，避免固定延遲後盲按快捷鍵。
- 長文翻頁依行號／頁面範圍與終點校驗，保留合法重複段落；不能只依文字相同便去重。
- 精華區遞迴走訪，保存目錄順序與路徑；辨識跨板連結、重複引用及循環，不能無限制跟隨。
- 每完成一篇就提交狀態；未完整讀完的內容保留為 partial，不能算成功。
- 結束前再次掃描清單，對帳期間新增、刪除與改編號情況。終端機爬取不是站台原子快照。
- 人工核對短文、長文、推文、最早與最新文章，以及精華深層目錄。
- 所謂「全部」是備份時點仍存在且帳號有權讀取的資料；不能保證復原伺服器已永久刪除的內容。

時間只先提供估算公式：總時間約為清單掃描＋各篇讀取時間＋精華走訪＋重試。假設平均每篇 2–5 秒，一萬篇純讀取約 5.6–13.9 小時；此為容量規劃假設，並非實測速度或站方建議速率。應由 200 篇試跑量測後再預估全量。

## 7. 儲存與介面邊界

保留文章擷取結果、必要的去敏終端機診斷資料、SQLite 索引、可攜 HTML 匯出及完整性報告。登入階段不保存含密碼的輸入紀錄。若有既有壓縮檔才另行保留與匯入。外部圖片網址先原樣保留；圖片檔另列選配下載任務，已失效的連結不能保證恢復。

本機服務僅綁定 127.0.0.1，加入本機會話與來源檢查。密碼不記錄到日誌或版本庫；正式登入、二階段驗證由使用者在本機完成。TLS 憑證及 SSH 主機金鑰需正常驗證。

目前專案位在 OneDrive 路徑。未來私人文章的預設資料目錄應與程式碼分開，讓使用者明確選擇是否同步到 OneDrive，不能把「在本機操作」等同於「資料永不進雲端」。

重用開源程式時核對其授權並保存要求的授權檔與來源資訊；不把伺服器端 boardd/mand 的存在當成一般使用者可呼叫的公開備份 API。

## 下一個具體里程碑

建立可顯示現行 PTT2 終端機畫面的本機連線原型，由使用者在本機登入，驗證 使用者個板（板名待使用者於工具輸入） 的 20 篇文章與精華子目錄讀取、保存和比對。這個里程碑完成後，才能宣稱下載流程通過實際帳號測試，再擴大至數千至上萬篇。目前只有端點連通已實測，下載器仍屬待實作、待驗證方案。
