# PTT／PTT2 文章下載與離線閱讀

目前版本為 **v2.23.0**。v2.1.0 之前的版本統稱 v1.x.x。

v2.23.0 一般逐行全程使用下鍵，沿用既有文字擷取與逾時處理，移除換鍵專用的拒存條件。正文逐行及逐頁間隔改為 0.1 秒。失敗或待核對的最近三個文章畫面會存入 log/readings，可開啟 HTML 查看，JSON 保留原始回應與配色供離線重播。

v2.22.4 暫存待確認的列直到下一屏核對。逐行讀到簽名與推文時，若仍能確認文章畫面，沿用下鍵。失敗紀錄加入最近畫面列寬、折行位置與文字摘要值。

v2.22.3 的 24 列讀法會辨識 PTT2 文字動畫提示並改讀有行號的原始內容。逐行以狀態列和已核對正文判斷是否仍在前進，跨屏驗證可延續尚未確認的列。

v2.22.2 核對畫面中段的折行與首屏列數偏移，並在擷取失敗時記錄最近送鍵與回應輪廓。

v2.22.1 核對頁尾靠近右緣的折行標記，並在下一屏驗證含超連結畫面的首屏行號偏移。未確認的折行仍留待查。

v2.22.0 可在起始編號輸入逗號分隔的多個篇號，依輸入順序讀取並保留續傳清單。單一編號仍與掃描篇數、方向搭配使用。

v2.21.1 保留首屏折行後可能多出的一行，經下一屏重疊核對後才採用。24 列備援和翻頁恢復會核對終端位置，並在 log 記錄備援停在哪一步。

v2.21.0 在畫面排版前解析 OSC 8 超連結，並以站方行號和畫面重疊正文核對自動折行。逐頁接縫無法確認時，正式下載可在核對位置後改用 24 列相容讀取。

v2.20.0 加入篇號加 Enter 定位、缺板名 ANSI 的檔名核對，並以正文、配色、連結和模板比對結果產生變動的離線文章。連續兩次在同篇、同階段和同畫面範圍中斷的讀取可留待查，於續傳核對 AID 後接續下載。正文逐行 ↓ 與逐頁 Page Down 的最短間隔為 0.2 秒。

v2.19.3 在續傳確認同一篇、且有至少兩次相同首屏失敗時保留待查並繼續。逐行讀取正文的 ↓ 間隔降至 0.5 秒。人工 ANSI 匯入記住搜尋根目錄並調整版面。

v2.19.2 在續傳時重新核對先前開文首屏無法辨識的篇號與 AID，將同一篇保留待查並繼續後續下載。

v2.19.1 在人工 ANSI 匯入後立即移除選單中的該項。錯漏清單仍保留自動讀取待查的紀錄。

v2.19.0 在正式批次遇到須按 ↑ 補查的逐頁接縫時，先回列表核對 AID，再用同一連線逐行重讀。逐篇待查通知可回查。「單篇測試修正」加入從既有待查紀錄選取目的地、預覽並匯入本機 ANSI 檔的介面。

v2.18.9 可使用 `manual_archive.py` 將本機 ANSI 檔匯入既有的待查項目，保留原檔與人工來源標記。讀取中斷時，若終端能確認已回看板列表，會保留待查並處理下一篇。

v2.18.8 在 24 列讀取中用重疊正文核對首列填充，並保留最近的折行比對診斷。

v2.18.7 在 24 列讀取中核對折行後每個畫面的重疊文字與配色，並記錄無法確認的行號偏移。

v2.18.6 修正 24 列畫面在未完成折行前有填充空列時的折行記號行號，並記錄接續核對所用的文章行號和重疊列數。

v2.18.3 改善 24 列相容讀取對跨列正文的核對，並在下載中斷時顯示已知的文章編號、AID 和階段。

v2.18.2 改善逐頁接縫補查。仍可辨認閱讀畫面時，返回列表核對 AID 再逐行重讀。無法確認終端位置時，保留進度與逐行重試紀錄，登入續傳後重讀同一篇。

v2.18.0 加入全板搜尋（`?`）、標題搜尋（`/`）、作者與 AID 查找、同主題快捷鍵及文章超連結。舊備份執行一次「離線內容重整」即可更新；移動備份時請保留 `search-data.js`。每筆處理後等待由 3 秒改為 1 秒，開正文前仍為 2 秒。

登入新下載和登入續傳都使用自動擷取。新下載預設補齊備份，續傳沿用原批次的範圍、方向、下載方式和已完成進度。自動擷取會直接使用已確認完整的單屏文章，遇到多頁文章則使用 Page Down 並核對接縫及文末。逐頁核對失敗且安全回到列表後，只對該篇逐行重讀一次。單篇測試的逐頁選項會直接呈現逐頁的結果。「單篇測試」可指定 AID、讀法和終端高度。每次測試會在程式資料夾的 `test-downloads/` 新建目錄，完成後可開啟該次結果。

雙擊 `start.bat` 開啟本機頁面。選擇 PTT 或 PTT2，輸入該站的帳密、可閱讀的板名和備份完整目錄。輸入框填根目錄，右側會顯示 `站台_板名`。上次欄位保存在本機設定，密碼和指定文章 AID 每次輸入。起始編號是第一個掃描的編號，填 0 就從站上最新一篇開始。預估下載範圍會隨起始編號、篇數及方向更新。篇數包含起始那篇。批次預設由新到舊，可切換為舊到新。操作與色彩細節請看首頁右上的「操作說明與紀錄」。

v2.10.0：備份 index.html 右上角「操作說明與紀錄」新增「錯漏紀錄」，列出未能下載／確認全文、保留舊備份、待核色、刪除／鎖定及原格式呈現失敗的編號、AID 和原因。單篇下載失敗也會建立索引和紀錄，但不會冒充成功文章。格式轉換失敗時保留純文字 HTML；磁碟寫入等全域錯誤仍停止匯出並記入 log。補抓或重整成功會清除對應待查，詳細歷史保留在 log。待核色仍保留 color_line_check.txt。舊備份請執行一次「離線內容重整」，不需登入；僅有已成功存檔的舊失敗不重新列為待查。紀錄只涵蓋已遇到問題，不代表已掃完整個看板，也無法自動判斷所有視覺差異。

同步程式碼時可排除 `.venv` 和所有 `__pycache__`。`.venv` 是本機 Python 虛擬環境，套件升級或重建環境時才需要更新。`__pycache__` 是 Python 執行時自動產生的快取。新副本用 Python 3.12 執行 `python -m venv .venv` 及 `.venv\Scripts\python.exe -m pip install -r requirements.txt`，再雙擊 `start.bat`。下載的文章另放在指定的備份資料夾。若也要備份文章，等任務結束後複製該資料夾，包含 `articles.sqlite3`、`index.html` 和 `articles/`。

不會寫入密碼或輸出 SDK 日誌；不會踢除其他登入連線。每次任務登入一次，遇錯即停止，不密集重試。二階段驗證尚未提供接續 UI，遇到會停止。此版不是完整互動終端機。

下載時逐篇寫入本機資料庫，以站台、看板和 AID 識別文章。「登入新下載」使用目前設定開啟新批次。「補齊備份」依 AID 沿用已存正文。「重新核對」重讀正文、推文和配色，以收錄站上修改。「登入續傳」沿用同站台、看板與備份目錄的未完成範圍、方向及備份方式。配色未完整對齊的正文仍可閱讀，待核色清單存在備份目錄的 `color_line_check.txt`。確定刪除、鎖定或無正文的項目在索引留提示，暫時無法讀取的項目留待續傳。診斷紀錄放在程式資料夾的 `log/`，包含實際掃描順序、各階段耗時、逐篇結果與配色覆蓋率。

下載按鈕下方會顯示各自的設定摘要。任務完成、中止、斷線或待處理時，頁面右下角會提醒。要收桌面通知，請點「啟用桌面通知」並允許瀏覽器權限，執行時保留下載頁開啟。

可先試跑 10～30 篇。等數篇存檔後按「停止」或暫時斷網，等程式完成本機整理後，重新輸入密碼並按「登入續傳」。核對是否沿用原範圍、方向及已存正文，並確認未完成的文章有接續。

匯出會在備份資料夾建立 `index.html` 和 `articles/`。每篇文章有一個可獨立開啟的 HTML 檔。移動備份時，將索引和 `articles/` 一起移動，便可保留相對連結。索引按文章編號 1～20、21～40 等固定範圍分頁，開啟時顯示最新一頁。舊文在上、新文在下。開啟索引時會選中第一個看板的最新一篇。按 ↑／↓ 選文，跨頁時會自動翻頁。Page Up／Page Down 切換較舊或較新的一頁，Enter 或 → 開啟文章。閱讀中按 ↓ 向下捲動一行，捲到底後再按 ↓ 開啟較新一篇。→ 往下 22 行，翻到底後再按 → 返回文章列表。看手動翻頁動畫時，可開啟「22 行視窗」。↑ 開啟較舊一篇，← 或 Esc 返回該篇在列表的位置。使用 Page Up／Page Down 可捲動長文。

舊版 PTT2 備份可直接轉換。填入放有 `articles.sqlite3` 的資料夾，點首頁的「離線內容重整」，無需登入。程式會把舊資料庫中的文章標為 PTT2，並更新該資料夾的 `index.html`。

要由新到舊掃描整板，請將起始編號填 0，掃描篇數填入看板的最新文章編號。篇數和最大編號可能不同。置底文盤點、精華區與全量一致性對帳仍待完成。

此版本使用 PyPtt WSS。文字與推文保留 SDK 回傳的全文和 JSON。單篇和批次下載都會擷取可對上正文的 ANSI 配色，未對上的行保留純文字。舊純文字備份或色碼對不完整的文章可用「重新核對」重抓。SSH 待實作。

ANSI 試跑請選 PTT、板名 `NctuNthuTYSH`、AID `1AdzogFB`，並使用一個測試用備份資料夾。由本機登入後會只下載〈色碼教學〉一篇。若配色未完整對齊，可在處理明細查看對齊行數。開啟 `index.html` 比對標題圖和正文配色，通過後再擴到多篇。支援基本八色、亮色、反白與重設。雙色字、閃爍及進階色票尚待驗證。

2,218 篇全新文章的固定等待時間約 3 小時 5 分。實際時間還包含站台查詢、讀文、翻頁和匯出。下載狀態會顯示新文章的平均處理秒數，並依試跑結果估算 2,218 篇所需時間。

PTT／PTT2 一般文章及 PTT 單篇 ANSI 曾由使用者試跑。v2.2.0 的批次續傳與待查流程已用模擬站台驗證，實站批次待驗證。
