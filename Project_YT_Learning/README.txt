YouTube Knowledge & Investment Immersion — Extension 0.9.0

本版重點
1. 開啟 YouTube 影片後，先嘗試從播放器已載入的字幕軌取得整份字幕；成功且最後時間戳接近影片結尾時立即完成。
2. 快速路徑若因 YouTube token／格式變動失敗，會自動開啟原生「顯示轉錄稿」面板，逐頁捲動並蒐集虛擬化的字幕列；不需要播放完整影片。
3. 僅在最後時間戳接近影片總長度時標示為完整；否則明確標成可能不完整，避免把部分字幕送入後續分析。
4. 保留可見字幕即時觀察，但與完整逐字稿分開儲存。
5. 合併即時字幕的重複觀察與逐步累積文字。
6. 手動貼上備援解析：支援 YouTube 複製格式（例如 3:103 分 10 秒字幕文字）、SRT、VTT、時間戳前綴純文字。
7. JSON 匯出包含 transcript 與 liveObservations 兩個獨立欄位。

安裝 / 更新
- 建議先備份 0.2 的資料與資料夾。
- 解壓縮本 ZIP。
- 為盡量保留 Chrome Extension ID 及既有 chrome.storage.local，請將本版檔案覆蓋到原本 0.2「載入未封裝項目」所使用的同一個資料夾路徑，再到 chrome://extensions 按該 Extension 的「重新載入」。
- 若改用新資料夾載入，Chrome 可能給不同 Extension ID，舊版本機儲存資料不會自動搬移。
- 若不想覆蓋，先停用 0.2，再以新資料夾載入 0.3；不要刪除舊資料夾。

使用與測試
- 開啟有字幕的 YouTube 影片，等待約數秒，側邊欄應顯示自動擷取狀態與段落數。
- 測試創作者字幕、自動生成字幕、日文字幕、長影片、影片 A/B/A 切換。
- 「重新檢查逐字稿」只作為測試/失敗重試入口；正常流程不需要按它。
- 若自動擷取失敗，請先確認 YouTube 影片本身有「顯示轉錄稿」功能，再匯出 JSON 或回報側邊欄狀態。
- 可用手動貼上作為備援；YouTube 複製格式會依第一個 m:ss 時間戳解析，丟棄後方重複的本地化時間標籤。

重要限制
- 字幕軌及逐字稿面板均為 YouTube 未保證穩定的內部頁面資料，YouTube 改版、PoToken 或反自動化調整可能使快速路徑失效；本版會退回面板路徑，但仍須持續實測。
- 面板路徑會以影片總長度及最後字幕時間戳判定完整性；總長度尚未載入、字幕本來就在結尾前結束或 YouTube 介面變動時，狀態會保守地顯示「可能不完整」。請在長影片測試時核對末段時間戳。
- 若影片沒有可用字幕，原生逐字稿不存在，這版不會自行執行 ASR。
- 這是技術原型，不代表已完成 YouTube 條款、商用權利或隱私法遵審查。
- 本版沒有 AI API、沒有後端；字幕與候選詞保存在本機 Chrome Storage。只有使用者展開某一候選詞時，該詞會送至 Wikipedia 查詢，完整字幕不會送出。


0.9.0 Live Track + Cue Highlight：播放器收到不同原文／翻譯字幕 payload 時，立即以最新請求取代現有逐字稿並重建詞雲，不再要求重新整理頁面；修正手動重新檢查的訊息名稱。專有名詞改以原始字幕 cue 記錄每一次出現時間，同時出現的多個詞可一起高亮，詳細卡片選擇最接近目前播放時間者。詞雲依首次出現時間排列，新增 Sudan／蘇丹。主畫面移除三組技術計數、完整逐字稿與即時觀察，重新檢查、JSON、匯入和診斷集中到頁尾工具區。

0.8.0 Multilingual Learning View：修正中文正則吞入整句、英文專名前置詞與跨語言固定中文標籤；擴充非洲／格陵蘭影片的中英實體回歸詞庫。Wikipedia 摘要與連結改為背景預載。播放到詞語出現時間時，文字雲會高亮並自動展開。母語預設中文，中文字幕先顯示 18 個、非中文字幕先顯示 60 個，其餘可按「想了解更多」。完整逐字稿預設收合，側欄另顯示原始字幕語言、人工／ASR 及 YouTube 翻譯目標。

0.7.0 High-precision Terms + Tag Cloud：取消「中文詞重複兩次即可入選」的低精度規則，改用書名符號、人名格式、學術詞後綴與可維護的多語實體詞庫；通用詞不再因高頻入選。所有結果以連續標籤文字雲顯示，點選後才展開摘要、連結及時間戳。Wikipedia 先以精確標題與重新導向查詢，修正「愛因斯坦」被模糊搜尋配到衛星詞條的問題。

0.6.0 Lazy Term Details + Caption Payload Merge：取得完整逐字稿後，自動以本機規則列出全部候選專有名詞，不再需要按分析按鈕。點選單一詞後才依序查詢影片語言 Wikipedia、英文 Wikipedia；都沒有可信結果時顯示 Google 搜尋連結。字幕攔截新增翻譯目標語言（tlang）辨識、同軌多 payload 合併、等待 UI 期間重新判定，以及不含字幕本文的 payload 段數／時間範圍診斷。


0.5.0 Rule-based Knowledge Terms：以本機語言分詞、專名格式、對數詞頻、跨段落分布與標題命中產生候選並排序。每個詞保留分數、排名訊號、原字幕證據及可跳轉時間戳。

0.4.0 Transcript Foundation：儲存可追溯的原始字幕 cues、分析用合併段落、純文字、字幕軌清單、語言、人工／ASR 類型、來源格式、覆蓋率、統計與 SHA-256。成功擷取會寫入 transcript_capture_success 診斷，避免 latest 仍停留在舊失敗。資料 schemaVersion 升為 4，供非 AI 專有名詞與 Ticker 關鍵字演算法使用。

0.3.5 新增：在 MAIN world 觀察 YouTube 播放器本來就為畫面字幕發出的 timedtext fetch／XHR，從不影響播放器的回應副本解析 JSON3、XML／srv3 或 WebVTT。這可避開「captionTracks baseUrl 回傳 HTTP 200 空本文」且影片又沒有逐字稿按鈕的組合。收到新字幕回應時會自動重新嘗試完整字幕；診斷摘要新增 payloads 數量。

0.3.4 新增：逐字稿入口會在 YouTube SPA 與播放器載入期間持續等待最多 18 秒，不再只檢查一次。失敗時狀態欄會顯示字幕軌／按鈕／面板／字幕列／video readyState 摘要；完整安全診斷寫入 captureDiagnostics 並隨 JSON 匯出，側欄亦可展開查看。診斷不包含字幕本文、Cookie 或字幕簽名網址。

0.3.3 修正：忽略 YouTube 預先建立但仍隱藏的逐字稿面板與隱藏按鈕；必要時先展開影片說明，再點擊真正可見的「顯示轉錄稿」。這會修正「按到隱藏按鈕後等待逾時」造成的 transcript_not_loaded。

0.3.2 新增：MAIN-world 字幕軌快速路徑（僅使用同頁 YouTube 字幕端點）；快速路徑失敗時改以可處理虛擬清單的面板逐頁捲動；資料會紀錄覆蓋率與完整／可能不完整狀態。

0.3.1 修正：擴大逐字稿 DOM 定位範圍與字幕列解析方式；擷取失敗原因會保存在側邊欄狀態欄，方便診斷。此版仍需在實際 YouTube 頁面驗證，不保證所有介面版本均可擷取。
